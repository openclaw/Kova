- Phases that drive Kova's conformance channel (support/plugins/kova-channel-probe) cannot record at this revision, because the plugin imports openclaw/plugin-sdk/channel-message, which OpenClaw removed in favour of openclaw/plugin-sdk/channel-outbound; they are written as they will run once the plugin is updated.
- In an isolated Kova home under /tmp with OCM 0.2.48 and Node 24.21.0, nine media and source-visible delivery rows of the probe scenario reported fewer deliveries than expected on OpenClaw 2026.9.9 and 2026.10.3, while the same code passed them with OCM 0.3.0 in an existing OCM store. The cause is not established (possibly /tmp to /private/tmp path resolution or the OCM version), so differences recorded by phases that drive media or source-visible delivery under such a setup are not yet attributable to the change.
- The template declares 103 product-command or unavailable-wrapper forms; only the Gateway-start helper is an existing callable script here. The command catalogue is absent in this checkout. The template is a derived plan, and these dependencies must be implemented and registered before it can record observations.
- Run 2 found 378/435 entry points, below the required nine-tenths share. The final condition-heading shares are 246/258 and 248/258, both above nine tenths; the finer condition-by-meaning shares are recorded separately in comparison.md. This reconciliation does not resolve the entry-enumeration acceptance gap.
- The background held-turn contract bounds admission separately from its lifetime and releases on join. Gateway restarts can interrupt that ambient condition; later phases must record interruption, and the dedicated restart flows create their own handles where recorded. Runtime continuity and cancellation have not been demonstrated.
- Repairing the conformance plugin import alone is insufficient for account, group, allowlist, mention and command-authorization observations. The present probe fixes default-account direct-chat facts and sets CommandAuthorized to true. The channel-probe-admission capability and --admission sdk wrapper path are additional unavailable prerequisites for those flows.
- The question, created-resource, configured-turn, debounce-overlap and suspension wrappers are declared orchestration, not implemented helpers. Their contracts include captured IDs, active lifetimes, configuration restoration and cancellation cleanup. The authored-fallback wrapper also needs access to the conformance runtime send context and an adapter that degrades data blocks to text.
- Supported action variants are kept separate: Telegram provides sticker search, Discord provides reaction listing and upload, Matrix provides profile changes and poll voting, iMessage provides the native attachment and message-effect actions, and Slack provides download. The last three adapters need real accounts; their phases remain outside reach while reachable sibling phases are retained.
- Startup inspection overlap requires a verified task-owned schema-inspection child on a host supporting pause/resume signals. - The origin-subject SDK condition requires the additional captured-control capability. No bundled adapter at this revision exposes that exact event mode; the conformance flow must retain the creator binding and compare it through the actual ingress resolver.
- iMessage upload-file, fresh-message unsend and message effects, plus Slack conversation-open/download and Matrix profile/poll voting, remain live-account variants. These real-account flows remain outside this template's reach; their future execution must supply owned platform cleanup rather than pretend an unsupported delete action exists.
